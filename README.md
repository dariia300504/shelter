# Система підтримки прийняття рішень персоналізованого підбору домашніх тварин із притулку

Ресурси програмного забезпечення, розробленого в магістерській кваліфікаційній роботі
(Ільчук Д. С., НУ «Львівська політехніка», 2026), та інструкція з його розгортання.

## 1. Склад ресурсів

| Файл / папка | Призначення | Додаток у роботі |
|---|---|---|
| `db/schema.sql` | SQL-скрипт створення бази даних: перелічувані типи, 7 таблиць, індекси, довідник критеріїв із початковими вагами | Додаток А |
| `app/matching.py` | Модуль підбору: нормалізація часткових оцінок, жорсткі критерії, зважене оцінювання з бонусом пріоритету, формування пояснень, Top-N | Додаток Б |
| `app/main.py` | API-сервер на FastAPI: збереження анкети, рекомендації, запис на зустріч, зміна ваг | Додаток В |
| `data/control_input.json` | Вхідні дані контрольного прикладу | Додаток Д |
| `data/control_output.json` | Очікуваний результат контрольного прикладу | Додаток Д |
| `tests/test_control.py` | Автоматична перевірка, що модуль підбору дає результат із додатка Д | — |
| `db/seed_demo.sql` | Демонстраційні дані (притулок, користувач, 4 тварини) для ручної перевірки API | — |
| `requirements.txt` | Перелік бібліотек Python | — |

Клієнтська частина (React) у додатках роботи не наводиться і до цих ресурсів не входить.
Для роботи з API можна використовувати вбудовану інтерактивну документацію Swagger UI (див. п. 5).

## 2. Технології

| Компонент | Версія |
|---|---|
| Мова програмування | Python 3.12 (сумісний із 3.10+) |
| Вебфреймворк | FastAPI ≥ 0.110, сервер Uvicorn ≥ 0.29 |
| Валідація даних | Pydantic 2 |
| СУБД | PostgreSQL 16 |
| Драйвер БД | psycopg 3 |
| Тестування | pytest |

## 3. Системні вимоги

- ОС: Windows 10/11, macOS або Linux.
- Процесор від 2 ядер, оперативна пам'ять від 4 ГБ, вільне місце на диску від 1 ГБ.
- Встановлені Python 3.10 або новіший і PostgreSQL 16.
- Доступ до інтернету для встановлення бібліотек.

## 4. Інструкція з розгортання

### Крок 1. Отримати код

```bash
git clone <адреса репозиторію>
cd pets-matching
```

або розпакувати архів `pets-matching.zip` і перейти в папку `pets-matching`.

### Крок 2. Створити віртуальне середовище і встановити бібліотеки

Linux / macOS:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows (PowerShell):
```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### Крок 3. Перевірити модуль підбору (база даних не потрібна)

```bash
python tests/test_control.py
```

Програма виведе ранжований список із чотирьох тварин (Барсик 0,92; Луна 0,86; Річі 0,78; Боня 0,61)
і повідомлення `OK: результат збігається з додатком Д`.
Альтернативно: `python -m pytest tests`.

### Крок 4. Створити базу даних

Від імені адміністратора PostgreSQL (наприклад, користувача `postgres`) створити користувача і базу:

```bash
psql -U postgres -c "CREATE USER app WITH PASSWORD 'app';"
psql -U postgres -c "CREATE DATABASE pets OWNER app;"
```

Створити структуру бази даних (додаток А):

```bash
psql -U app -d pets -f db/schema.sql
```

За потреби завантажити демонстраційні дані:

```bash
psql -U app -d pets -f db/seed_demo.sql
```

### Крок 5. Налаштувати підключення до бази даних

Сервер читає рядок підключення зі змінної середовища `DATABASE_URL`.
Якщо її не задано, використовується значення за замовчуванням
`postgresql://app:app@localhost/pets`, яке відповідає кроку 4.

Інші параметри задаються так:

Linux / macOS:
```bash
export DATABASE_URL="postgresql://користувач:пароль@сервер:5432/pets"
```

Windows (PowerShell):
```powershell
$env:DATABASE_URL = "postgresql://користувач:пароль@сервер:5432/pets"
```

### Крок 6. Запустити API-сервер

```bash
cd app
uvicorn main:app --host 127.0.0.1 --port 8000
```

Після запуску сервер доступний за адресою http://127.0.0.1:8000.

## 5. Перевірка роботи

Відкрити в браузері http://127.0.0.1:8000/docs — інтерактивну документацію Swagger UI,
у якій можна виконати всі запити.

| Метод і шлях | Призначення | Відповідь |
|---|---|---|
| `POST /questionnaire` | збереження анкети користувача | `questionnaire_id` |
| `GET /recommendations?questionnaire_id=1&top=10` | формування рекомендацій | ранжований список тварин із поясненнями |
| `POST /appointments?animal_id=1` | бронювання тварини для зустрічі | новий статус `booked`; повторний запис — помилка 409 |
| `PUT /admin/criteria` | зміна ваг м'яких критеріїв | кількість оновлених критеріїв; сума ваг ≠ 1 — помилка 422 |

Приклад анкети для `POST /questionnaire` (після завантаження `seed_demo.sql`):

```json
{
  "user_id": 1,
  "housing_type": "квартира",
  "suitable_for_large": false,
  "experience": 1,
  "has_children": false,
  "has_pets": false,
  "preferred_species": "собака",
  "allowed_species": "кіт",
  "age_min_months": 12,
  "age_max_months": 60,
  "activity_level": 0.5,
  "time_per_day": 2.0
}
```

Після цього запит `GET /recommendations?questionnaire_id=1` поверне список тварин,
у якому великий пес Рекс відсутній, оскільки не проходить жорсткий критерій відповідності житловим умовам.

## 6. Розгортання на сервері

Для розгортання на віддаленому сервері (VPS або хмарний сервер):

1. Встановити Python і PostgreSQL або використати керовану хмарну СУБД PostgreSQL.
2. Виконати кроки 1–5, вказавши в `DATABASE_URL` адресу робочої бази даних.
3. Запустити сервер з кількома робочими процесами:
   ```bash
   cd app
   uvicorn main:app --host 0.0.0.0 --port 8000 --workers 2
   ```
4. Налаштувати автоматичний запуск сервера як системної служби (наприклад, systemd у Linux).
5. Розмістити перед сервером вебсервер Nginx як зворотний проксі з сертифікатом HTTPS,
   оскільки персональні дані користувачів мають передаватися лише захищеним з'єднанням
   (підрозділ 4.1.10 роботи).

## 7. Обмеження прототипу

Прототип реалізує основний цикл підбору. Реєстрація й автентифікація користувачів,
розмежування доступу за ролями, редагування карток тварин через інтерфейс,
оформлення усиновлення й повернення, журнал змін ваг і статистика спроєктовані
в роботі, але в цьому прототипі не реалізовані.
